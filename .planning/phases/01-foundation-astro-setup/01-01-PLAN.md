  <action>
Create content collection schemas based on actual Jekyll frontmatter structure. Schemas must be permissive enough to accept existing content.

1. Create src/content.config.ts with collections:

Publications schema (from _publications/*.md analysis):
- title: z.string()
- collection: z.literal('publications')
- permalink: z.string() (for URL preservation)
- date: z.coerce.date()
- venue: z.string()
- citation: z.string()
- paperurl: z.string().optional() (not all have it)
- excerpt: z.string().optional() (only some have it)

Talks schema (from _talks/*.md analysis):
- title: z.string()
- collection: z.literal('talks')
- type: z.string() (Talk, Tutorial, Conference proceedings talk)
- permalink: z.string()
- venue: z.string()
- date: z.coerce.date()
- location: z.string()

Posts schema (for _posts/*.md):
- title: z.string()
- date: z.coerce.date()
- tags: z.array(z.string()).optional()
- permalink: z.string().optional()

Portfolio schema (for _portfolio/*):
- title: z.string()
- excerpt: z.string().optional()
- collection: z.literal('portfolio').optional()

2. Use glob() loader pattern (Astro 5.x):
   loader: glob({ pattern: "**/*.md", base: "./src/content/{collection}" })

3. Create empty directories with .gitkeep files:
   - src/content/publications/.gitkeep
   - src/content/talks/.gitkeep
   - src/content/posts/.gitkeep
   - src/content/portfolio/.gitkeep

The actual content migration happens in Plan 02.
  </action>
