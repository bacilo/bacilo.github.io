<task type="auto">
  <name>Task 2: Create CMS user guide documentation</name>
  <files>docs/CMS-USER-GUIDE.md</files>
  <action>
Create `docs/CMS-USER-GUIDE.md` -- a task-oriented user guide for the CMS. Structure the guide around what the user DOES, not what the CMS features ARE (per research: "document tasks, not features").

**Sections:**

**1. Quick Start (First-Time Setup)**
- Step-by-step PAT creation (follow research Example 2 closely):
  - GitHub Settings > Developer settings > Personal access tokens > Fine-grained tokens
  - Token name: "CMS Access - bacilo.github.io"
  - Repository access: Only bacilo/bacilo.github.io
  - Permissions: Contents (Read and write), Metadata (Read-only)
  - Copy and store securely
- Navigate to https://bacilo.github.io/admin/
- Paste PAT, click Login
- Security notes: token expiration, minimal permissions, revocation

**2. Creating Content** (one subsection per collection)
- **Blog Posts:** Required fields (title, date), optional (tags, permalink), body (markdown). Date format: YYYY-MM-DD. Tags: comma-separated list.
- **Publications:** Required fields (title, date, venue, citation, permalink), optional (paperurl, excerpt), body. Citation uses multi-line text widget. Collection field auto-set.
- **Talks:** Required fields (title, date, type, venue, location, permalink), body. Type examples: "Talk", "Keynote", "Workshop". Collection field auto-set.
- **Portfolio:** Required fields (title), optional (excerpt, repoUrl, demoUrl, description, playgroundUrl), body. URL fields must be valid URLs (https://...).

For each collection: which fields are required, what format they expect, and what the slug pattern produces (filename convention).

**3. Editing and Deleting Content**
- How to find and edit existing content
- Save creates a Git commit automatically
- Delete removes the file and commits

**4. Media Library**
- Uploading images (stored in public/images/uploads/)
- Inserting images into markdown body
- Image appears at /images/uploads/[filename] on the site

**5. Validating Your Changes**
- Run `bash scripts/validate-cms-content.sh` after editing
- What errors mean and how to fix them (Zod schema errors = field format mismatch)
- Run `npm run build` to ensure full site builds

**6. Troubleshooting**
- "Authentication failed" -- check token permissions, expiration, repository access
- "Session expired" -- browser cleared localStorage, re-authenticate with same PAT
- Build fails after CMS edit -- check field formats match schema requirements
- Image not showing -- verify path starts with /images/uploads/
- /admin/ returns 404 locally -- use /admin/index.html on dev server (production resolves correctly)

**7. Schema Reference**
- Brief table linking each collection to its Zod schema in content.config.ts and CMS config in config.yml
- Note about schema synchronization: changes to content.config.ts must be mirrored in config.yml

Do NOT include Mermaid diagrams or screenshots (research marked these as optional; keep documentation simple and text-based for maintainability). Do NOT document Sveltia CMS generic features -- only document THIS site's specific setup and collections.
