<task type="auto">
  <name>Task 2: Defensive responsive CSS for 320px viewports (QUAL-02)</name>
  <files>src/styles/themes/minecraft.css</files>
  <action>
Add defensive CSS rules inside minecraft.css to prevent 320px viewport overflow. The research identified these risk areas:

1. **Press Start 2P heading overflow**: Add `word-break: break-word; overflow-wrap: break-word;` to `[data-theme="minecraft"] h1`, `[data-theme="minecraft"] h2`, and `[data-theme="minecraft"] h3` rules. Press Start 2P is a fixed-width bitmap font that cannot naturally break long words. This prevents headings like "Recent Publications" from creating horizontal scroll at 320px.

2. **Author sidebar at 320px**: Verify the existing `@media (max-width: 768px)` rule hides the sidebar on non-home pages. For the home page sidebar (which stays visible), add inside a new `@media (max-width: 480px)` block: `[data-theme="minecraft"] .author-sidebar { max-width: 100%; box-sizing: border-box; }` to prevent the 250px sidebar from overflowing the 320px viewport.

3. **Code block overflow**: Verify that `.astro-code` already has `overflow-x: auto` set (either in minecraft.css or inherited). If not present, add `[data-theme="minecraft"] .astro-code { overflow-x: auto; max-width: 100%; }`.

4. **Card grid**: Verify `.portfolio-grid` uses `auto-fill, minmax(280px, 1fr)` which collapses to 1 column at 320px. No changes expected — just confirm.

5. **Footer decorative elements**: Verify `footer::before` (48px creeper) and `footer::after` (90px hearts) are centered and fit within 320px. Both are well under 320px. No changes expected.

Place all responsive additions in a clearly commented section at the end of minecraft.css:
```css
/* ===== Phase 25: 320px Responsive Fixes ===== */
```

After changes, run `npx astro build` to verify no CSS errors.
