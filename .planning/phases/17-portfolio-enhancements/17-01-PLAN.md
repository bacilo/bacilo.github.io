**GitHubCard.astro changes:**

1. Add `statsDisplay` prop to the Props interface:
```typescript

  repoUrl: string;
  title: string;
  description?: string;
  image?: string;
  slug?: string;
  statsDisplay?: 'stars' | 'downloads' | 'both' | 'none';
}
```

2. Destructure the new prop with default:
```typescript
const { repoUrl, title, description, image, slug, statsDisplay = 'stars' } = Astro.props;
```

3. Add `data-stats-display={statsDisplay}` attribute to the `.github-card` div.

4. Update the HTML template `.repo-stats` section to conditionally render based on `statsDisplay`:
   - If `statsDisplay === 'none'`: omit the `.repo-stats` div entirely
   - If `statsDisplay === 'stars'` or `statsDisplay === 'both'`: show the existing stars span
   - If `statsDisplay === 'downloads'` or `statsDisplay === 'both'`: add a new downloads span: `<span class="downloads">Downloads: <span class="download-count">-</span></span>`
   - Always show language span when stats are visible (statsDisplay !== 'none')

5. Update the `<script>` section:
   - Import `fetchReleaseStats` alongside `fetchRepoData`
   - Read `statsDisplay` from `data-stats-display` attribute
   - Only call `fetchRepoData` if statsDisplay includes stars (is 'stars' or 'both')
   - Only call `fetchReleaseStats` if statsDisplay includes downloads (is 'downloads' or 'both')
   - For downloads: sum all asset download_count values from the release response: `releases.assets.reduce((sum, asset) => sum + asset.download_count, 0)`
   - Format download count with `.toLocaleString()`
   - If statsDisplay is 'none', skip all API calls
   - Maintain existing error handling (show "Unable to load stats" on failure)

6. Add CSS for the `.downloads` span matching existing `.stars` style:
```css
.repo-stats .downloads {
  color: var(--color-text-muted);
}

.repo-stats .download-count {
  color: var(--color-text);
  font-weight: 500;
}
```
