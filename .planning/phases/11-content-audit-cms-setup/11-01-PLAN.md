  <name>Task 1: Create frontmatter audit script and fix violations</name>
  <files>package.json, scripts/audit-frontmatter.mjs, src/content/posts/*.md</files>
  <action>
1. Install gray-matter as dev dependency:
   `npm install --save-dev gray-matter`

2. Create `scripts/audit-frontmatter.mjs` that:
   - Reads all `.md` files from `src/content/posts/`
   - Parses frontmatter using gray-matter
   - Validates against the posts Zod schema (mirror from content.config.ts):
     ```
     z.object({
       title: z.string(),
       date: z.coerce.date(),
       tags: z.array(z.string()).optional(),
       permalink: z.string().optional(),
     })
     ```
   - Reports: file name, pass/fail, specific field errors, any extraneous fields not in schema
   - Exits with code 1 if any violations found, 0 if all pass
   - Uses zod (already available via astro dependency -- import from 'zod' or install explicitly if needed)

3. Run the audit script: `node scripts/audit-frontmatter.mjs`

4. If violations are found, fix them directly in the markdown files:
   - Remove any extraneous frontmatter fields not in the schema (e.g., `collection`, `layout`, or other Jekyll-era leftovers)
   - Ensure `date` is in YYYY-MM-DD format
   - Ensure `tags` is an array of strings (not a single string)
   - Ensure `title` exists and is a string
   - Do NOT remove `permalink` (it is in the schema as optional)
   - Do NOT alter the markdown body content

5. Re-run the audit script to confirm all posts now pass.

Note: The blog posts collection schema does NOT include a `collection` field (unlike publications/talks). If any blog posts have `collection: posts` in frontmatter, that is an extraneous field and should be removed.
  </action>
