<task type="auto">
  <name>Task 1: Build verification and CSS requirement audit</name>
  <files>src/styles/themes.css, src/styles/global.css, src/layouts/BaseLayout.astro</files>
  <action>
    Run `npm run build` to verify the Astro site builds successfully with all LEGO theme fonts and styles.

    Then audit themes.css and global.css programmatically using grep/search to verify all 13 v4.0 requirements have corresponding CSS implementations:

    **VIS-01 (Color palette):** Verify `--color-lego-red`, `--color-lego-blue`, `--color-lego-yellow`, `--color-lego-green`, `--color-lego-gray` custom properties exist in `[data-theme="lego"]` block.

    **VIS-02 (Baseplate grid):** Verify `[data-theme="lego"] body` has `repeating-linear-gradient` background-image with `24px 24px` background-size.

    **VIS-03 (Component transform):** Verify `[data-theme="lego"]` selectors exist for: `.site-header`, `.site-title`, `nav`, `nav a`, `.author-sidebar`, `.github-card`, `.repo-link`, `.astro-code`, `footer`, `footer a`.

    **BRICK-01 (Card depth):** Verify `.github-card` has multi-layer `box-shadow` (3 comma-separated shadow values on desktop).

    **BRICK-02 (Card studs):** Verify `.github-card::before` has `radial-gradient` stud pattern with `pointer-events: none`.

    **BRICK-03 (Nav buttons):** Verify `nav a` has `box-shadow`, `nav a::before` has radial-gradient studs, `nav a:active` has `translateY(2px)`.

    **BRICK-04 (Code blocks):** Verify `.astro-code` has `border: 3px solid var(--color-lego-blue)` and `box-shadow`.

    **TYPE-01 (H1 Fredoka):** Verify `[data-theme="lego"] h1` has `font-family: 'Fredoka'` and `font-weight: 700`.

    **TYPE-02 (H2-H3 Slackey):** Verify `[data-theme="lego"] h2` and `h3` have `font-family: 'Slackey'`.

    **TYPE-03 (Body Baloo 2):** Verify `[data-theme="lego"] body` has `font-family: 'Baloo 2'`.

    **ANIM-01 (Bounce animations):** Verify `.github-card` and `nav a` have `transition` with `cubic-bezier(0.34, 1.56, 0.64, 1)` easing. Verify card hover uses `scale(1.03)` and nav hover uses `translateY(-2px)`.

    **ANIM-02 (Reduced motion):** Verify `@media (prefers-reduced-motion: reduce)` block exists with `transition: none !important` for `nav a` and `.github-card`. Verify static `:active` state preserved (`translateY(2px)`).

    **RESP-01 (Mobile sidebar):** Verify global.css has `@media (max-width: 768px)` with `.author-sidebar { display: none }` and `body.page-home .author-sidebar { display: block }`. Verify BaseLayout.astro adds `page-home` class conditionally.

    Also verify font imports exist in BaseLayout.astro:
    - `@fontsource/fredoka/700.css`
    - `@fontsource/slackey`
    - `@fontsource/baloo-2/400.css`
    - `@fontsource/baloo-2/600.css`

    Calculate WCAG AA contrast ratios for key LEGO color pairs:
    - Black (#000000) on gray (#e4e4e4): must be >= 4.5:1
    - Muted (#555555) on gray (#e4e4e4): must be >= 4.5:1
    - White (#ffffff) on red (#d11013): must be >= 4.5:1 for normal text, >= 3:1 for large text
    - White (#ffffff) on blue (#0055bf): must be >= 4.5:1 for normal text, >= 3:1 for large text

    Use the WCAG relative luminance formula:
    L = 0.2126 * R + 0.7152 * G + 0.0722 * B (with sRGB linearization)
    Contrast ratio = (L1 + 0.05) / (L2 + 0.05)

    Record all results (pass/fail with evidence) for the validation report.

<task type="auto">
  <name>Task 2: Lighthouse performance audit and validation report</name>
  <files>.planning/phases/21-integration-validation/21-01-VALIDATION-REPORT.md</files>
  <action>
    Build the site and serve it locally, then run Lighthouse CLI against it with LEGO theme.

    **Performance audit steps:**
    1. Run `npm run build` to generate production build
    2. Serve the dist/ folder locally using a static server (e.g., `npx serve dist -l 4321`)
    3. Run Lighthouse CLI against localhost:
       ```
       npx lighthouse http://localhost:4321 --only-categories=performance,accessibility --output=json --output-path=./lighthouse-lego.json --preset=desktop --chrome-flags="--headless=new --no-sandbox"
       ```
       Note: Since Lighthouse runs against localhost, and the LEGO theme requires user interaction to select (localStorage), we need to assess the baseline site performance. The LEGO theme's CSS is always loaded (themes.css is imported globally), so the CSS payload is identical regardless of active theme. The primary additional payload is the 170KB of Fontsource fonts. Lighthouse auditing the default theme gives us the performance baseline; fonts are loaded regardless of active theme since they're imported in BaseLayout.
    4. Extract performance score and key metrics (LCP, FCP, CLS, TBT)
    5. If Lighthouse is not available or fails, document the limitation and assess performance based on:
       - Astro static site (zero client JS except theme switcher and copy buttons)
       - 170KB total font payload (Fontsource with font-display: swap)
       - CSS-only animations (no JS animation runtime)
       - CSS custom properties for theming (no runtime computation)

    **Create validation report** at `.planning/phases/21-integration-validation/21-01-VALIDATION-REPORT.md` containing:

    1. **Build Status:** Pass/Fail
    2. **Requirement Audit:** Table with all 13 requirements, CSS evidence, and pass/fail
    3. **Color Contrast Results:** Table with 4+ color pair calculations and WCAG AA verdict
    4. **Performance Results:** Lighthouse scores or qualitative assessment
    5. **Structural Integrity:**
       - All LEGO selectors scoped to `[data-theme="lego"]`
       - No LEGO styles can leak to other themes
       - Font imports present with correct weights
       - Reduced-motion support verified
       - Mobile responsive rules verified
    6. **Issues Found:** Any failures or concerns requiring remediation
    7. **Recommendations:** Items for manual verification in Plan 02

    The report should clearly indicate which requirements PASS automated validation and which need manual visual confirmation in Plan 02.
