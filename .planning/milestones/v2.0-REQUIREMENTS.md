# Requirements: Personal Website CMS

**Defined:** 2026-02-13
**Core Value:** A professional online presence that showcases work and is easy to maintain with monthly content updates

## v2.0 Requirements

Requirements for CMS integration milestone. Each maps to roadmap phases.

### CMS Infrastructure

- [x] **CMS-01**: User can access admin interface at /admin route
- [x] **CMS-02**: User can authenticate with GitHub Personal Access Token
- [x] **CMS-03**: User's auth persists across browser sessions

### Content Editing — Blog

- [x] **BLOG-01**: User can create new blog posts via CMS
- [x] **BLOG-02**: User can edit existing blog posts via CMS
- [x] **BLOG-03**: User can delete blog posts via CMS
- [x] **BLOG-04**: User can use rich text markdown editor for post body

### Content Editing — Publications

- [x] **PUB-01**: User can create new publications via CMS
- [x] **PUB-02**: User can edit existing publications via CMS
- [x] **PUB-03**: User can delete publications via CMS

### Content Editing — Talks

- [x] **TALK-01**: User can create new talks via CMS
- [x] **TALK-02**: User can edit existing talks via CMS
- [x] **TALK-03**: User can delete talks via CMS

### Content Editing — Portfolio

- [x] **PORT-01**: User can create new portfolio items via CMS
- [x] **PORT-02**: User can edit existing portfolio items via CMS
- [x] **PORT-03**: User can delete portfolio items via CMS

### Media Management

- [x] **MEDIA-01**: User can upload images through CMS interface
- [x] **MEDIA-02**: User can browse uploaded images in media library
- [x] **MEDIA-03**: User can insert images into content from media library

### Content Normalization

- [x] **NORM-01**: All existing blog posts have consistent frontmatter structure
- [x] **NORM-02**: All existing publications have consistent frontmatter structure
- [x] **NORM-03**: All existing talks have consistent frontmatter structure
- [x] **NORM-04**: All existing portfolio items have consistent frontmatter structure

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Multi-user roles/permissions | Single user only, unnecessary complexity |
| OAuth proxy infrastructure | PAT auth eliminates need, simpler for single user |
| Real-time collaboration | Single author, not needed |
| Netlify Identity | Deprecated as of 2026 |
| Comments system | Complexity not worth it for monthly updates |
