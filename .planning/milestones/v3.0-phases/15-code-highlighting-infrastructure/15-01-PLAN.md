  <name>Task 1: Configure Shiki dual themes in astro.config.mjs and add theme-coordination CSS to themes.css</name>

  <action>
**Step 1: Add Shiki dual-theme configuration to astro.config.mjs.**

Add a `markdown` block to the existing `defineConfig` call. Do NOT change any existing config (site, integrations, output). Add the following property at the same level as `site`, `integrations`, and `output`:

```javascript
markdown: {
  shikiConfig: {
    themes: {
      light: 'github-light',
      dark: 'github-dark',
    },
    wrap: true,
  },
},
```

This enables Astro's built-in Shiki to generate CSS variables `--shiki-light`, `--shiki-light-bg`, `--shiki-dark`, `--shiki-dark-bg` on every code block. The `wrap: true` enables line wrapping for mobile.

Do NOT add a `langs` array — Astro/Shiki auto-detects languages from code fences.

**Step 2: Append code block theme coordination CSS to the END of src/styles/themes.css.**

After the existing synthwave theme block (the last theme definition), add a new section with a clear comment header. The CSS must:

1. **Default (light theme):** `:root .astro-code, :root .astro-code span` → use `--shiki-light` and `--shiki-light-bg` with `!important` (overrides Shiki's inline styles).

2. **Dark theme:** `[data-theme="dark"] .astro-code, [data-theme="dark"] .astro-code span` → use `--shiki-dark` and `--shiki-dark-bg` with `!important`.

3. **Auto theme (dark preference):** Nest inside `@media (prefers-color-scheme: dark)` with `[data-theme="auto"]` selector — same as dark.

4. **Light-based novelty themes:** `[data-theme="sepia"] .astro-code, [data-theme="sepia"] .astro-code span, [data-theme="lego"] .astro-code, [data-theme="lego"] .astro-code span` → use `--shiki-light` variables with `!important`.

5. **Dark-based novelty themes:** `[data-theme="terminal"] .astro-code, [data-theme="terminal"] .astro-code span, [data-theme="minecraft"] .astro-code, [data-theme="minecraft"] .astro-code span, [data-theme="synthwave"] .astro-code, [data-theme="synthwave"] .astro-code span` → use `--shiki-dark` variables with `!important`.

6. **Base code block styling:** `.astro-code` gets `border: 1px solid var(--color-border)`, `border-radius: 4px`, `padding: var(--space-sm)`, `margin: var(--space-sm) 0`, `font-size: 0.9em`. These use the existing CSS custom property system from Phase 14 so borders adapt to each theme.

The `!important` declarations are required because Shiki generates inline `style` attributes on each `<span>` and the `<pre>` element. Without `!important`, theme switching will not work.
  </action>

**Step 1: Update portfolio page code styles (src/pages/portfolio/[...slug].astro).**

The existing `.content :global(pre)` styles set `background: var(--color-header-bg)` which will conflict with Shiki's theme-aware backgrounds. Update the existing `pre` and `code` styles:

- `.content :global(code)` — keep `font-family: var(--font-mono)`, `font-size: 0.9em`, `padding: 0.2em 0.4em`, `border-radius: 3px`. Keep `background: var(--color-header-bg)` for INLINE code only (not inside pre).
- `.content :global(pre)` — REMOVE `background: var(--color-header-bg)` (Shiki's CSS variables handle this). Keep `padding: var(--space-sm)`, `border-radius: 4px`, `overflow-x: auto`, `margin: var(--space-sm) 0`. Add `font-size: 0.9em`.
- `.content :global(pre code)` — keep `background: none`, `padding: 0`, `font-size: inherit`.

The key change: the `<pre>` background must NOT be hardcoded because `.astro-code` (which IS the `<pre>` element) gets its background from `--shiki-light-bg` or `--shiki-dark-bg` via themes.css. The existing `background: var(--color-header-bg)` on `pre` would override Shiki's theme colors.
