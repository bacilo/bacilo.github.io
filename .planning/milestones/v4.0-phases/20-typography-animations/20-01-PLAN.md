  <name>Task 1: Install Fontsource packages and import fonts in BaseLayout</name>
  <files>package.json, src/layouts/BaseLayout.astro</files>
  <action>
    1. Install Fontsource font packages:
       ```bash
       npm install @fontsource/fredoka @fontsource/baloo-2 @fontsource/slackey
       ```

    2. In `src/layouts/BaseLayout.astro`, add font imports in the frontmatter section (after existing imports, before the Props interface):
       ```typescript
       import '@fontsource/fredoka/700.css';      // Bold weight for H1 titles
       import '@fontsource/slackey';              // Regular weight (only available) for H2-H3
       import '@fontsource/baloo-2/400.css';      // Regular weight for body text
       import '@fontsource/baloo-2/600.css';      // SemiBold for bold/emphasis
       ```

    These imports go in the Astro frontmatter (between the --- fences). Astro automatically injects the corresponding @font-face declarations into the page head. Fontsource includes `font-display: swap` by default, preventing FOIT.

    Do NOT add `<link rel="preload">` tags — Fontsource handles font loading with swap, and preload paths may break between dev and production builds (see research open question #2). The swap strategy ensures text is always visible.

    Use static fonts (not variable) per research recommendation: 170KB total vs 240KB for variable fonts, and we only need specific weights.
  </action>
  <verify>
    Run `npm run build` — build succeeds without errors. Check that `@fontsource/fredoka`, `@fontsource/slackey`, and `@fontsource/baloo-2` appear in package.json dependencies.
  </verify>
  <done>
    Fontsource packages installed, font CSS imported in BaseLayout.astro frontmatter, Astro build succeeds.
  </done>

<task type="auto">
  <name>Task 2: Add LEGO typography hierarchy, hover animations, and reduced-motion support</name>
  <files>src/styles/themes.css</files>
  <action>
    Add the following CSS rules to `src/styles/themes.css`, placed AFTER the existing LEGO component overrides (after the `[data-theme="lego"] footer a:hover` block) and BEFORE the LEGO mobile performance section.

    **Typography (TYPE-01, TYPE-02, TYPE-03):**

    ```css
    /* LEGO typography hierarchy */
    [data-theme="lego"] h1 {
      font-family: 'Fredoka', var(--font-system);
      font-weight: 700;
    }

    [data-theme="lego"] h2,
    [data-theme="lego"] h3 {
      font-family: 'Slackey', var(--font-system);
      font-weight: 400;  /* Slackey only has regular weight */
    }

    [data-theme="lego"] body {
      font-family: 'Baloo 2', var(--font-system);
      font-weight: 400;
    }

    [data-theme="lego"] strong,
    [data-theme="lego"] b {
      font-weight: 600;  /* Baloo 2 SemiBold for emphasis */
    }
    ```

    Note: Do NOT add font-size or line-height overrides — preserve the existing sizing from global.css. Only change font-family and font-weight. The fallback `var(--font-system)` ensures text renders if custom fonts fail.

    **Hover animations (ANIM-01):**

    Update the EXISTING `[data-theme="lego"] .github-card` rule to include transform transition alongside existing box-shadow/border-color transitions:
    ```css
    [data-theme="lego"] .github-card {
      /* Existing properties preserved: border, border-radius, background, position, box-shadow */
      transition:
        transform 300ms cubic-bezier(0.34, 1.56, 0.64, 1),
        box-shadow 0.2s ease,
        border-color 0.2s ease;
    }
    ```

    Update the EXISTING hover rule to add transform:
    ```css
    [data-theme="lego"] .github-card:hover,
    [data-theme="lego"] .github-card:focus-within {
      transform: scale(1.03);  /* Subtle scale with bounce — 1.03 not 1.05 to avoid layout shift */
      border-color: var(--color-lego-red);
      box-shadow: /* existing hover shadows preserved */
    }
    ```

    Update the EXISTING `[data-theme="lego"] nav a` rule to add hover lift transition alongside existing 34ms pressed-state transition. The nav a rule already has `transition: transform 34ms ease-out, box-shadow 34ms ease-out, color 0.2s ease;` — update to:
    ```css
    [data-theme="lego"] nav a {
      /* All existing properties preserved */
      transition:
        transform 250ms cubic-bezier(0.34, 1.56, 0.64, 1),
        box-shadow 250ms ease-out,
        color 0.2s ease;
    }
    ```

    Update the EXISTING nav hover rule to add lift:
    ```css
    [data-theme="lego"] nav a:hover {
      color: var(--color-lego-yellow);
      transform: translateY(-2px);  /* Lift with bounce */
      box-shadow:
        0 4px 8px rgba(0, 0, 0, 0.2),
        0 0 0 2px var(--color-lego-yellow);
    }
    ```

    The existing active/pressed state (`transform: translateY(2px)`) remains unchanged — the 34ms was for the pressed state, but the overall transition timing now uses 250ms for the hover lift (the active override still produces instant visual feedback due to the direction of movement).

    **Reduced motion (ANIM-02):**

    The existing `@media (prefers-reduced-motion: reduce)` block in themes.css already covers `nav a` and `.github-card`. Verify it still sets `transition: none !important` for both selectors. The existing block is sufficient since it already covers the elements we added transitions to.

    Important: The `!important` on `transition: none` overrides the new Phase 20 transition values. Static hover states (transform, box-shadow, color changes) still apply instantly without animation when reduced motion is active.
  </action>
